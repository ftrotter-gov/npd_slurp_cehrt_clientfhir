# Parser Output Structure

## Overview

The FHIR parser generates **two parallel data schemas** organized into separate directories:

```
parser_output/
├── fhir_analysis/          # Full FHIR metadata for debugging and analysis
├── npd_compliant/          # Minimal NPD-compliant schema for database import
└── (legacy files at root)  # Generated by parallel merge process
```

## Why Two Schemas?

The parser extracts data for two distinct purposes:

1. **FHIR Analysis** (`fhir_analysis/`): Preserves complete FHIR metadata including lineage, validation results, and full field coverage. Used for:
   - Debugging FHIR resource processing
   - Data quality analysis
   - Endpoint discovery (Step52)
   - Field coverage reporting

2. **NPD Compliant** (`npd_compliant/`): Stripped-down schema matching the National Plan and Provider Directory (NPD) specification. Used for:
   - PostgreSQL database imports
   - NPD-compliant data warehousing
   - Minimal schema applications

## Directory Contents

### `fhir_analysis/` - Full FHIR Metadata

**Core Tables:**
- `endpoint_instance.csv` - Complete endpoint records with UUIDs, original IDs, full URLs, vendor names, timestamps, validation results
- `endpoint_to_npi.csv` - Endpoint-to-NPI mappings with validation status
- `organization.csv` - Organization records with full metadata
- `ehr_vendor.csv` - EHR vendor directory
- `data_lineage.csv` - Data provenance and lineage tracking
- `field_coverage_log.csv` - Field processing coverage statistics

**Lookup Tables:**
- `endpoint_connection_type.csv`
- `environment_type.csv`

**Contact Tables:**
- `fhir_organization_address.csv`
- `fhir_organization_phone.csv`
- `fhir_organization_email.csv`
- `fhir_organization_contact_url.csv`

### `npd_compliant/` - NPD Schema

**Core Tables:**
- `endpoint_instance.csv` - Minimal endpoint schema (id, ehr_vendor_id, address, connection_type_id, name, description, environment_type_id)
- `endpoint_to_npi.csv` - Simple endpoint-NPI mapping (endpoint_instance_id, other_id, system, issuer_id)
- `organization.csv` - NPD organization schema (id, authorized_official_id, ein_id, parent_id)
- `ehr_vendor.csv` - Vendor directory

**Lookup Tables:**
- `endpoint_connection_type.csv`
- `environment_type.csv`
- `fhir_address_use.csv`, `fhir_phone_use.csv`, `fhir_email_use.csv`
- `payload_type.csv`, `mime_type.csv`

**Address Tables:**
- `address.csv` - Address entity pointers
- `address_us.csv` - US addresses (validated/parsed)
- `address_international.csv` - International addresses
- `address_nonstandard.csv` - Non-standard addresses

**Relationship Tables:**
- `organization_to_address.csv`
- `organization_to_phone.csv`
- `endpoint_instance_to_payload.csv`

## Key Differences

| Feature | FHIR Analysis | NPD Compliant |
|---------|---------------|---------------|
| **Schema Complexity** | Full FHIR resources | Minimal normalized schema |
| **Columns** | All FHIR fields + metadata | Only NPD-required fields |
| **Lineage** | Complete provenance tracking | None |
| **Validation** | Detailed validation results | Basic format only |
| **Timestamps** | Yes (created_at) | No |
| **Original IDs** | Preserved | Not included |
| **Purpose** | Analysis & debugging | Database import |

## UUID Consistency

**IMPORTANT:** Both schemas use the **same UUID5 identifiers** for cross-referencing:

```python
# Same endpoint in both schemas
fhir_analysis/endpoint_instance.csv:
  id: "d84a21f1-e982-510e-a81c-cbf8be5def46"
  
npd_compliant/endpoint_instance.csv:
  id: "d84a21f1-e982-510e-a81c-cbf8be5def46"
```

This allows joining data between schemas when needed.

## File Naming Conventions

### Clarity Improvements

Original name → New name (in respective directories):
- `endpoint_instance_to_other_id.csv` → `endpoint_to_npi.csv` (clearer purpose)
- `npd_endpoint_instance.csv` → `endpoint_instance.csv` (npd_ prefix removed in npd_compliant/ directory)

### Prefix Handling

- **FHIR directory**: Keeps original names (e.g., `fhir_organization_address.csv`)
- **NPD directory**: Strips `npd_` prefix for cleaner names (e.g., `endpoint_instance.csv` instead of `npd_endpoint_instance.csv`)

## Using the Data

### For Endpoint Discovery (Step52)

```python
# Read from FHIR analysis directory
npi_file = Path(input_dir) / 'fhir_analysis' / 'endpoint_to_npi.csv'
endpoint_file = Path(input_dir) / 'fhir_analysis' / 'endpoint_instance.csv'
```

### For Database Import

```sql
-- Use NPD compliant directory
COPY endpoint_instance FROM 'parser_output/npd_compliant/endpoint_instance.csv' WITH CSV HEADER;
COPY endpoint_to_npi FROM 'parser_output/npd_compliant/endpoint_to_npi.csv' WITH CSV HEADER;
```

### For Analysis

```python
# Use FHIR analysis directory for complete metadata
import pandas as pd

# Get detailed lineage
lineage = pd.read_csv('parser_output/fhir_analysis/data_lineage.csv')

# Get validation results
endpoint_to_npi = pd.read_csv('parser_output/fhir_analysis/endpoint_to_npi.csv')
print(endpoint_to_npi[['endpoint_instance_id', 'is_valid_format', 'is_valid_api', 'validation_error']])
```


## Common Issues

### Issue: "Cannot find npd_endpoint_instance_to_other_id.csv"

**Solution:** Use the new organized structure:
```python
# Instead of:
'npd_endpoint_instance_to_other_id.csv'

# Use:
'npd_compliant/endpoint_to_npi.csv'  # For NPD import
# OR
'fhir_analysis/endpoint_to_npi.csv'  # For analysis with validation data
```

### Issue: "Column not found"

**Solution:** Check which schema you need:
- Need `is_valid_format`, `is_valid_api`, `validation_error`? → Use FHIR analysis schema
- Need minimal columns for database? → Use NPD compliant schema

### Issue: "UUIDs don't match between files"

**Solution:** Ensure you're reading from the same processing run. The UUIDs are deterministic and will match within a run, but may differ if data was reprocessed.

## Generated By

- `cehrt_fhir_parser/merge_parallel_outputs.py` - Merges parallel processing runs
- `cehrt_fhir_parser/cli.py` - Main entry point (Step 45)
